# Быстрые проверки и выпуск

## Локальная работа

На каждой итерации: `python3 scripts/check.py`. Это форматирование и проверка типов всех Rust-целей без линковки приложения. При изменении конкретной логики дополнительно запускай ее тесты: `cargo test --locked <имя_теста>`.

Перед push: `python3 scripts/check.py --full`. Команда запускает строгий Clippy, полный набор обычных Rust-тестов и тесты протокола Nintendo. Она не повторяет `cargo check` перед Clippy. `--target <triple>` позволяет проверить выбранную установленную цель. На Windows подходит `python` вместо `python3`.

Нативная проверка: собери приложение через `cargo build --locked --bin console-link`, затем запусти `python3 scripts/smoke-native.py target/debug/console-link` (на Windows добавь `.exe`). Если задан `CARGO_TARGET_DIR` или `--target`, передай фактический путь к бинарнику. Проверка требует графической сессии и GPU. Она подтверждает показ кадров и три режима окна, но не заменяет осмотр интерфейса, реальную карту захвата или Discord.

## GitHub Actions

1. **PR: Native builds.** На macOS arm64 и Windows x64 выполняются форматирование, Clippy, тесты, нативный smoke и проверка установки компонентов Nintendo. Установщики и release-профиль не собираются. Новая итерация отменяет устаревший автоматический прогон.
2. **main: Native builds.** Те же проверки и сборка release-кандидатов идут параллельно. Пакеты проходят нативный GPU smoke; Windows дополнительно проверяет install/reinstall/uninstall, URL protocol, сохранность пользовательских файлов и отсутствие внешней зависимости от Visual C++ runtime. Артефакты `release-*` хранятся 14 дней. Их можно скачать для проверки до публикации.
3. **Выпуск: Publish tested release.** Выбери `main`, укажи ID успешного полного прогона Native builds и тег, совпадающий с его версией в Cargo.toml. Публикация скачивает готовые пакеты, проверяет источник, версию и состав файлов, создает SHA256SUMS.txt и выпускает prerelease. Rust повторно не компилируется. Тег указывает на SHA исходного прогона, даже если main уже продвинулся.

Пример после обновления версии и успешного CI:

```sh
gh run list --workflow ci.yml --branch main --status success
gh workflow run release.yml --ref main -f build_run_id=123456789 -f release_tag=v0.7.1
```

Публикация запрещена для PR, чужого репозитория, другой ветки или workflow, незавершенного/неуспешного прогона и существующего тега. Успешная проверка только Nintendo не содержит release-артефактов и не может выпустить приложение. Если пакеты истекли, запусти полный Native builds на main заново. Прогон публикации не отменяется новой сборкой.

Компилятор CI закреплен на Rust 1.100.0, проверенном релизом 0.7.0. Обновляй его осознанно в `ci.yml`; смена toolchain делает кэш холодным. Проверки и release используют отдельные кэши зависимостей. CI отключает debug symbols для dev/test; оптимизация release, ThinLTO и static CRT Windows не изменены. ZIP/EXE загружаются без повторного сжатия контейнера Actions.

## Измеренная исходная стоимость

В [прогоне 0.7.0](https://github.com/Potanull/console-link/actions/runs/43541930168) этапы шли последовательно:

| Этап | Windows | macOS |
| --- | ---: | ---: |
| Clippy | 210 с | 128 с |
| Rust tests | 296 с | 157 с |
| Debug application build | 30 с | 16 с |
| Release build + packaging | 500 с | 295 с |
| Сохранение кэша | 72 с | 65 с |

Новый flow убирает release build из PR, перекрывает его по времени с тестами на main и полностью исключает сборку при публикации. Это структурное сокращение работы; длительность нового CI нужно измерить после первого и повторного прогона. Очередь GitHub runners и холодный кэш могут оставаться заметной частью ожидания. Числа выше не являются обещанием времени нового выпуска.
