# Console Link 0.3: игровой режим и Discord

## Поручение пользователя

Автоматически выбирать размер захвата и предпочитать 60 FPS по умолчанию; ручные параметры перенести в настройки. Добавить обычное, безрамочное и полноэкранное окно, больше горячих клавиш. При начале игры обычное меню исчезает, настройки вызываются боковым оверлеем поверх изображения; завершение игры возвращает обычный интерфейс. После этого добавить вход Discord для статуса и продумать отключаемое определение игры.

## Принятые решения реализации

- По умолчанию автоматическая политика, номинальные 60 FPS; из реально доступных режимов сначала выбирается подходящий FPS, затем разрешение. 720p60 предпочтительнее 1080p30. NTSC 59,94 сохраняется без округления capture timestamps. При отсутствии 60 FPS используется реальный доступный fallback с явным указанием фактического режима. Ручной выбор остается в настройках.
- Обычное окно имеет рамку; безрамочное окно сохраняет оконный размер; полноэкранный режим использует механизм ОС, без обещания exclusive display mode. Предпочтение сохраняется.
- Для надежного repaint используется один root viewport: во время игры он отображает изображение, а обычный интерфейс не рисуется. Размер и положение обычного интерфейса сохраняются и восстанавливаются. Закрытие окна во время игры завершает сессию и возвращает меню, закрытие обычного меню завершает приложение.
- F1 вызывает боковую панель; Esc сначала закрывает панель, затем выходит из полноэкранного режима. Дополнительные клавиши управляют fullscreen, режимами окна, скриншотом, mute, громкостью и завершением сессии. Они действуют при фокусе приложения. Ввод текста не должен запускать буквенные shortcuts.
- Панель рисуется поверх игрового кадра и поэтому видна в захвате окна Discord/OBS. Сохраненный PNG по-прежнему содержит исходный кадр без панели.
- Вход Discord: public OAuth client, PKCE S256, только scope identify; стандартный OAuth подтверждает профиль, а существующий локальный Discord IPC отправляет Rich Presence. Перед отправкой сравниваются профиль OAuth и пользователь настольного Discord. Токены хранятся в OS credential store, не в JSON настроек.
- Зарегистрированный Discord Application ID общий для сборки; обычным пользователям не требуется Developer Portal. Регистрацию нового приложения поручил пользователь; вход владельца/согласие с условиями и реальная выдача OAuth требуют его участия.

## Авторизация: проверенные границы

Rich Presence через desktop IPC не требует OAuth. Scope identify не дает права менять activity через HTTP. Общие rpc scopes ограничены партнерами и не используются. Официальный discovery Discord объявляет public token authentication none и PKCE S256, но raw secretless flow должен быть подтвержден реальным code exchange после регистрации Public Client. До этого вход не считается проверенным.

Redirect предлагается фиксированный loopback `http://127.0.0.1:45961/discord/callback`, зарегистрированный точно. Callback server ограничен loopback, проверяет путь, state, Host, метод, размеры и время ожидания. Клиент не содержит Client Secret. Браузер открывается только после явного действия пользователя.

## Определение игры: предложение, а не готовая функция

HDMI не предоставляет надежного идентификатора игры. Первая полезная версия: локальный OCR на HOME/title screen, ограниченный каталог и предложение с подтверждением. Последнее подтвержденное название сохраняется, ручной ввод имеет приоритет. Анализ по умолчанию отключен; выключение останавливает работу и освобождает очередь. Кадры не отправляются в облако и не сохраняются ради анализа. Универсальное определение по любому gameplay не обещается. Реализация этой функции отдельно согласуется после проверки полезности сценария.

## Проверка

Политика выбора режима, устаревшие настройки 30 FPS, NTSC, fallback, manual strict mode, window/overlay transitions, текстовый фокус shortcuts, ограничения FPS и OAuth state/PKCE/callback parsing проверяются тестами. Визуально проверяются обычное меню, игра с оверлеем и компактное окно. Реальный OAuth code exchange и отправка активности проверяются только после owner setup. Основная аппаратная приемка карты остается отдельной от UI/CI.
